# 个人外链云端同步

范围包括本人的自定义外链、标签、标签关联、笔记和外链日志。公开外链目录继续随 Astro 静态构建发布，个人记录存入 Cloudflare D1，由 Worker 提供访问接口。不需要租用或维护服务器，不开放注册，也不接入评论服务。

## 日常使用

在外链手册点击“连接个人云端”，输入个人同步口令。其他设备输入相同口令即可使用同一份记录。连接会保留 30 天；口令通过 HTTPS 发送一次，浏览器使用 HttpOnly 会话 Cookie，网页脚本不保存口令。

保存外链日志后自动同步，标签和笔记等停止编辑一秒后自动同步；切回页面或页面保持可见时每 30 秒检查云端。离线期间继续保存本机记录，网络恢复后可点击“立即同步”重试。断开同步会撤销当前设备的云端会话，本机记录仍保留。

首次连接时：

- 云端没有记录：上传本机记录。
- 本机没有个人记录：读取云端记录。
- 两边已有不同记录：提示选择保留哪份，不自动覆盖。

使用已同步的基准识别后续改动。两台设备都修改后，会显示冲突提示。选择覆盖前，将被替换的一份保存为当前浏览器的恢复备份，可点击“导出恢复备份”下载，再用原有导入功能恢复。每个浏览器保留最近一次恢复备份。上传使用数据库版本比较，过期版本会被拒绝，避免多端写入静默覆盖。

标签移除需要先确认，取消按钮默认获得焦点。全局标签进入回收站，保留标签名称、原关联外链和移除时间，可以立即撤销，或在刷新后从“标签回收站”恢复。回收站和其他个人记录一起跨设备同步，并包含在 JSON 导出中。恢复标签只补回标签和关联，不会回滚之后编辑的笔记或其他标签。恢复时若已有同名标签，会合并关联。回收站中的标签可点击“彻底删除”，再次确认后删除标签及原关联，无法撤销或恢复；外链和笔记保留。彻底删除会随个人数据同步到其他设备，过期版本上传仍会被拒绝。

个人数据格式为 v6，自动兼容 v1/v2/v3/v4/v5 本地数据和备份。外链日志与其他个人记录一起备份和同步，保存日志后自动上传；没有日志的旧备份会迁移为空日志列表。服务端也会把旧页面移除的标签放入回收站，并保留旧页面未识别的回收站内容。旧页面遇到新版云端记录时会停止自动同步，刷新页面即可使用新版。回收站最多保留 200 个标签，达到上限时可先恢复或彻底删除部分标签；未腾出空间前阻止继续移除，避免自动丢弃历史标签。

## 本地验证

```sh
npm ci
cp worker/.dev.vars.example worker/.dev.vars
```

把 `worker/.dev.vars` 中的测试口令换成至少 8 个字符的值。该文件已被 Git 忽略，仅用于本地开发。

```sh
npm run sync:migrate:local
npm run sync:dev
```

另一个终端运行：

```sh
PUBLIC_LINK_SYNC_URL=http://localhost:8787 npm run dev
```

通过 `http://localhost:4321/links/` 打开网页。前后端使用同一个主机名 `localhost`，跨端口允许访问；不要混用 `127.0.0.1` 和 `localhost`。

```sh
npm test
npm run check
npm run build
```

## 首次上线

1. `npx wrangler login` 连接管理 `builtbyluna.cc` 的 Cloudflare 账号。
2. 本项目的 `worker/wrangler.jsonc` 已填写线上数据库 ID。新建独立实例时，使用 `npx wrangler d1 create luna-links-personal --config worker/wrangler.jsonc` 创建数据库，再替换 `database_id`。
3. `npm run sync:migrate` 创建线上数据表。
4. 设置并妥善保存一个至少 8 个字符的同步口令，推荐使用密码管理器生成的较长随机值。运行 `npx wrangler secret put SYNC_KEY --config worker/wrangler.jsonc`，按提示输入。不要把口令放入 Git、`PUBLIC_*` 变量或聊天记录。
5. `npm run sync:deploy` 部署 Worker；配置会绑定 `links-sync.builtbyluna.cc`。Worker 服务和网站使用同一主域名，以支持浏览器的 SameSite 会话 Cookie。
6. 在 GitHub 仓库 Actions Variables 中设置 `PUBLIC_LINK_SYNC_URL=https://links-sync.builtbyluna.cc`，再运行网站原有的 GitHub Pages 部署。未设置此变量时，网页继续使用原本的本地存储。

生产接口仅接受来自 `https://builtbyluna.cc` 的请求；本地开发命令单独覆盖允许的来源。不要给生产服务添加 `*` 来源，也不要把本地测试口令用于线上。

## 维护

前端继续由原有 GitHub Pages workflow 发布。修改 Worker 代码后运行 `npm run sync:deploy`；新增数据库迁移后先运行 `npm run sync:migrate`。

更换 `SYNC_KEY` 会立即使旧会话失效，其他设备需要重新连接。数据库只保存会话令牌的哈希值，口令不写入数据库。每分钟每个 Cloudflare 节点最多约 5 次连接尝试；这只是辅助限流；较短的口令更容易被猜到，知道口令的人可以访问和修改个人记录。

浏览器的 JSON 导出继续保留，建议在批量导入或清理数据前备份。Cloudflare 的免费额度有用量上限，账号控制台可以查看使用量。

本版将个人记录保存为单份文档，限制为 UTF-8 编码后 1.9 MB，以留出 D1 单值容量余量。超出时拒绝上传并保留本机记录，不会截断笔记。

可选的 `TAG_RECOVERY_MODE=1` 会暂时拒绝所有个人数据和会话请求，用于管理员提取历史记录前暂停读写；日常应保持为 `0` 或不设置。维护期间本机改动继续保留。执行数据库历史恢复前必须先完整备份，并在提取完成后恢复当前数据库、核对一致，再解除维护状态。

新增日志功能上线时，先部署新版 Worker，再发布前端，无需数据库迁移。服务端保留 v1/v2/v3 页面写入时未识别的日志，防止旧标签页清空日志。

新增个人外链功能上线时，同样先部署新版 Worker，再发布前端，无需数据库迁移。个人外链最多 1000 个，和关联的笔记、标签及标签回收站一起导入、导出和同步。旧版页面写入时，服务端会保留它无法识别的个人外链及相关记录。导入旧备份会将个人外链列表迁移为空，导入前请先导出当前备份。

熟悉度和复习功能已下线。为兼容已有本机备份和云端数据，`records` 中旧的 `level`、`seen` 字段仍按原格式保留，不再用于页面展示、筛选、统计或交互；笔记、标签、个人外链与日志继续正常保存和同步。这一界面简化无需数据迁移。

费用标签编辑使用 v6 的 `feeOverrides`，按外链 ID 保存个人选择，优先于预置费用；空数组表示用户主动移除所有费用标签，不能回退到预置值。修改包含在 JSON 备份、恢复备份和云端同步中，即使仅移除费用标签也会上传。旧备份升级时默认没有费用修改；导入旧备份会替换当前修改，导入前建议导出备份。上线时先部署新版 Worker，再发布前端，无需数据库迁移；v1～v5 旧页面写入时服务端会保留已有费用修改，旧页面需要刷新后使用新版。
